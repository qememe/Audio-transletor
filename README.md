# AudioALL

Русскоязычная программа для передачи изображений, текста, аудио- и видеофайлов **звуком**: динамик → микрофон, звуковой кабель или аудиозапись WAV. Общее Java-ядро используется настольной программой и нативным Android-приложением. Интернет для работы не нужен.

## Готовые сборки

После сборки файлы находятся в `dist/`:

| Платформа | Файл / запуск |
| --- | --- |
| Linux x86_64 | `AudioALL-linux-x86_64.tar.gz`; распаковать и запустить `AudioALL/bin/AudioALL` |
| Android 8.0+ | `AudioALL-android.apk`; установить APK, разрешить микрофон при первом приёме |
| Linux / Windows с Java 8+ | `AudioALL.jar`; `java -jar AudioALL.jar` |
| Windows | `run-windows.bat` рядом с JAR; самостоятельную EXE-сборку создаёт `scripts/build-windows.ps1 -Package` на Windows с JDK 17+ |

Linux-архив включает Java runtime: отдельно Java устанавливать не требуется. Нужны графическое окружение, системные библиотеки X11/fontconfig/ALSA и звуковой сервер вашей системы. Android APK подписан локальным ключом разработки; он подходит для прямой установки. Для публикации используйте собственный постоянный ключ.

## Возможности

- **SSTV encode и decode:** Robot 36, Robot 72, PD 50, PD 120, Martin 1; VIS-заголовок с чётностью, автоматическое определение режима, построчный приём, сохранение PNG. Перед отправкой изображение вписывается в размер режима с сохранением пропорций.
- **Текст:** UTF-8, включая русский язык и emoji.
- **Аудио, видео и любые файлы:** точная передача байтов, имя и MIME-тип, DEFLATE при выигрыше размера, SHA-256 файла, CRC-32 каждого пакета, Hamming SECDED и 1–3 повтора пакетов.
- **Звуковые модемы:** 4FSK 300, 4FSK 600, AFSK Bell 202 1200. Приём определяет все три автоматически.
- Отправка через динамик, приём с микрофона, выбор аудиоустройств, экспорт сигнала в WAV и декодирование WAV. WAV вход: PCM16 mono/stereo 8–192 кГц; выход: PCM16 mono 48 кГц.
- Передача и приём запускаются **независимо и одновременно**. На входе параллельно работают SSTV и все цифровые декодеры. Кодирование WAV также доступно во время приёма.
- Linux: выбор папки приёма, просмотр картинки/сообщений, открытие файлов. Android: системный выбор файлов, просмотр картинки/текста, сохранение копии и передача принятого файла другим приложениям.

**Аудио и видео передаются файлами.** MP3, OGG, WAV, MP4, WebM и другие контейнеры не перекодируются и восстанавливаются побайтно. Воспроизведение принятого файла выполняет установленный системный проигрыватель. Программа не реализует видеозвонки, потоковый видеокодек или встроенную запись с камеры.

Все перечисленные протоколы имеют и передатчик, и приёмник на обеих платформах. Стандартные SSTV-сигналы предназначены для обмена с другими SSTV-программами. Цифровой пакетный формат AudioALL/1 работает между экземплярами AudioALL: Bell 202 здесь обозначает физическую модуляцию, **не AX.25/APRS**.

## Как пользоваться

См. [пошаговое руководство](docs/QUICKSTART.md).

1. На принимающем устройстве нажать **«Включить приём»** и выбрать микрофон.
2. На передающем выбрать тип, файл / текст, протокол и **«Передать звуком»**.
3. Дождаться полного сигнала. Картинка появляется построчно; цифровой файл сохраняется после получения всех пакетов и проверки SHA-256.
4. Проверка без микрофона: **«Сохранить WAV»**, затем открыть полученный WAV кнопкой **«Открыть WAV для приёма»** на другом устройстве.

## Реальные ограничения

- Звуковой канал имеет низкую скорость: полезная скорость цифровых данных до повторов и метаданных — примерно 324 бит/с для 4FSK 300 и 644–649 бит/с для 4FSK 600 / Bell 202. Например, несжимаемый файл 100 КиБ с двумя повторами занимает примерно 42 минуты в быстром режиме и 84 минуты в устойчивом. Интерфейс показывает консервативную оценку времени до сжатия.
- Максимум цифрового файла — **8 МиБ**. Практично использовать сообщения, очень короткие сжатые записи и небольшие клипы. Обычный длинный видеоролик может передаваться несколько дней.
- RIFF WAV ограничен 4 ГБ. Экспорт сверх этого предела прекращается с ошибкой; промежуточный файл удаляется. Длительную передачу можно выполнять непосредственно через динамик.
- Одновременная работа TX/RX реализована программно. При взаимной передаче на одинаковых частотах через общий воздух сигналы смешиваются: используйте независимые звуковые тракты/кабели. Разделение двух наложенных передач и компенсация собственного эха не реализованы. Каждое устройство может принять собственную передачу.
- Приём SSTV требует начала сигнала с VIS-заголовком. Есть синхронизация по строкам и небольшая коррекция периода, но нет ручного выбора режима при пропущенном заголовке или полноценной коррекции сильного наклона/частотного сдвига.
- Для Android держите приложение на экране; оно не даёт экрану погаснуть во время TX/RX. Фоновый микрофонный сервис не реализован. При уничтожении Activity операции отменяются.
- Цифровые повторы — без подтверждения и автоматической повторной передачи. При потере пакетов показывается незавершённый приём. Новый запуск передачи создаёт новый ID; возобновление незавершённого сеанса между перезапусками не реализовано.
- Передачи открытые, без шифрования. Приложение никогда автоматически не запускает принятые файлы.

## Сборка

### Linux / переносимый JAR

Нужны JDK 17+, Bash, Python 3 (для APK), `tar`.

```sh
./scripts/test.sh
./scripts/build-desktop.sh
./scripts/package-linux.sh
```

### Android без Gradle

Нужны JDK 17+ и официальный Android SDK: `platforms;android-35`, `build-tools;35.0.0`.

```sh
sdkmanager 'platforms;android-35' 'build-tools;35.0.0'
export ANDROID_SDK_ROOT=/path/to/android-sdk
./scripts/build-android.sh
```

Сборка использует `javac → aapt2 → d8 → zipalign → apksigner`, без AndroidX/Gradle и внешних зависимостей приложения. APK содержит DEX и общую Java-библиотеку, поэтому подходит для ARM/ARM64/x86/x86_64. Для своего ключа задайте `AUDIOALL_KEYSTORE`, `AUDIOALL_KEY_ALIAS`, `AUDIOALL_STORE_PASSWORD`, `AUDIOALL_KEY_PASSWORD`. Сохраните ключ, которым подписали APK, для будущих обновлений.

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1
# Самостоятельная EXE + встроенная Java, выполняется на Windows:
powershell -ExecutionPolicy Bypass -File scripts\build-windows.ps1 -Package
```

### Командная строка

```sh
java -jar dist/AudioALL.jar encode --text 'Привет, звук!' --profile FAST --repeat 2 --out message.wav
java -jar dist/AudioALL.jar encode --image photo.png --mode PD120 --out image.wav
java -jar dist/AudioALL.jar encode --file clip.mp4 --kind VIDEO --profile FAST --out clip.wav
java -jar dist/AudioALL.jar decode --wav message.wav --out received
java -jar dist/AudioALL.jar devices
```

Режимы: `ROBOT36`, `ROBOT72`, `PD50`, `PD120`, `MARTIN1`. Профили: `ROBUST`, `FAST`, `BELL202`. Типы файлов: `AUDIO`, `VIDEO`, `FILE`.

## Проверка и структура

[Отчёт о проверке](docs/VALIDATION.md), [описание протоколов и источники](docs/PROTOCOLS.md).

- `core/src` — DSP, SSTV, модем, контроль целостности, WAV.
- `desktop/src` — Swing, Java Sound, CLI.
- `android/src` — Android Activity, AudioRecord/AudioTrack, безопасный ContentProvider.
- `tests/src` — проверки ошибок FEC, целостности, шумового канала, всех режимов SSTV и WAV.
- `scripts` — воспроизводимые сборки и запуск.
