# Проверка сборки 1.0.0

Проверено 10 октября 2026 года. Ядро и настольная программа: OpenJDK Temurin 17, Linux x86_64 / WSLg. Android: SDK Platform 35, Build Tools 35.0.0, minimum API 26.

## Автоматические проверки ядра

`./scripts/test.sh`: **6705 утверждений, все проходят**.

- Hamming SECDED: все 256 байтов; отсутствие ошибок; исправление каждой из 13 одиночных ошибок; обнаружение тестируемых двойных ошибок.
- Конверты всех четырёх типов: TEXT/AUDIO/VIDEO/FILE; точное восстановление байтов; нормализация имени; отказ при повреждённом SHA-256.
- Все три модема: произвольный сдвиг начала записи, 52% исходной амплитуды, добавленный гауссов шум, непредсказуемые границы блоков PCM, дедупликация повторов.
- Потеря одной полной копии каждого пакета: файл восстанавливается из оставшейся копии во всех трёх профилях.
- FAST: восстановление при расхождении частоты дискретизации на 100 ppm, одновременно с шумом и потерей одного повтора.
- Последовательный SSTV и все четыре типа файлов в одном непрерывном автоматически распознаваемом входе.
- Одновременные передача и приём между двумя экземплярами Receiver по независимым PCM-каналам, с разными профилями и типами данных.
- WAV PCM16: UTF-8/emoji, stereo 44.1 кГц, пересчёт на 48 кГц, нечётный вспомогательный RIFF-блок с padding.
- SSTV WAV, заканчивающийся точно на границе растра: завершение FM-фильтра и сохранение последней строки.

## SSTV: наше кодирование → наш приём

Градиентная RGB-картинка; RMSE измерен по всем трём каналам, диапазон 0–255. SSTV аналоговый: точное побайтное совпадение изображения не ожидается.

| Режим | RMSE | Длительность WAV, с VIS и тишиной |
| --- | ---: | ---: |
| Robot 36 | 6.52 | 37.130 с |
| Robot 72 | 3.83 | 73.130 с |
| PD 50 | 2.65 | 50.814 с |
| PD 120 | 3.19 | 127.233 с |
| Martin 1 | 1.07 | 115.420 с |

Длительность каждого режима совпадает с публичными таймингами в пределах 1 мс.

## Независимый передатчик SSTV

`PySSTV 0.5.9 → WAV → AudioALL CLI`: режим распознаётся по VIS, полное изображение сохраняется, размеры совпадают. Для PD 50 использован класс PD90 с публичными параметрами `VIS_CODE=93`, `PIXEL=0.286`; код модуляции и формирования WAV остался из PySSTV.

| Режим | RMSE |
| --- | ---: |
| Robot 36 | 6.65 |
| Martin 1 | 1.06 |
| PD 50 | 2.89 |
| PD 120 | 3.35 |

Воспроизведение проверки: установите `PySSTV==0.5.9` и `Pillow` в отдельное Python-окружение, затем `python scripts/reference-check.py`. Эти пакеты нужны только для этой проверки, не для программы.

Robot 72 проверен внутренним round trip и публичными таймингами, но не независимым передатчиком. Обратное направление в сторонние SSTV-приёмники отдельно не проверялось.

## Готовые приложения

- Настольное окно успешно создано, показано в WSLg, выполнены layout и отрисовка; [снимок интерфейса](desktop.png).
- CLI собранного JAR кодирует и декодирует русское сообщение с emoji.
- Командная строка **Java runtime из готовой Linux-сборки** кодирует и декодирует сообщение. Это проверяет состав модулей встроенного runtime.
- APK: javac/D8/aapt2 прошли; ZIP/DEX/manifest/resources целы; `zipalign -c -p 4` проходит; `apksigner verify` подтверждает подписи v2 и v3. APK содержит Java DEX без архитектурно зависимых нативных библиотек.
- [GitHub Actions: Linux/Android и Windows](https://github.com/qememe/Audio-transletor/actions/runs/38050679290): оба задания успешно завершены, включая автоматическое создание Windows EXE с runtime.
- Готовый Windows `AudioALL.exe` запущен через Windows interop: закодировал русскоязычное/Unicode-сообщение в WAV. Готовый Linux launcher успешно декодировал этот WAV, сообщение совпало. Аппаратный звук Windows отдельно не проверялся.

## Практические пределы проверки

Физический телефон не подключён. Установка APK, микрофон/динамик Android и реальные акустические передачи между устройствами **не проверены на оборудовании**. В текущем Linux-окружении Java Sound не обнаружил аппаратных звуковых устройств; интерфейс и операции с WAV проверены.

Шумовые проверки моделируют простой звуковой канал, а не все эффекты комнаты, радиоканала, эха, нелинейного динамика, AGC и шумоподавления. Два одновременно наложенных сигнала на одном канале не разделяются. Нет измерений устойчивости к сильному частотному сдвигу или большого расхождения тактов.
